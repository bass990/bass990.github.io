ChainPilot

Supply-chain disruption agent

Detects a stock-out or supplier delay, runs ten tool calls, has specialists argue when confidence is low, drafts RFQs and a Slack alert, and stops at a human-approval gate above a trust threshold that moves with rated outcomes. Live tool feed over SSE, React UI, single Docker image with a recorded replay mode.

What the eval found

Across 204 runs on Sonnet 5, plain direct synthesis scored 0.735 strict accuracy against 0.382 with always-on deliberation. My conditional gate was the least stable branch: its trigger flipped on 12 of 34 scenarios. Direct synthesis is now the default and the gate is a flag.

TriageIQ

ER triage decision support

A symptom specialist flags red flags, a senior-nurse synthesizer assigns the ESI level, care area and action checklist. Nurse override with a required reason, printable report, hash-chained audit log. Mock patients only, labelled as such on every screen. Haiku 4.5 for the specialists, Sonnet 5 for synthesis.

What the eval found

Across 270 runs, a single prompt scored 100% on ESI level and produced no report at all on 12 of 99 attempts, all on ambiguous cases. The lean pipeline scored 98.9% and never failed to produce one. Zero critical misses on both. That completeness row is why lean is the default.

ClauseGuard

Contract-conflict agent

Extracts clauses from two PDFs, finds and ranks every conflict, drafts a redline brief, and has a second model review each suggested resolution. A 24-entry negotiation playbook is exposed as a tool. Advice to counsel, never an executed amendment.

What the eval found

Across 450 runs on Sonnet 5, the agentic loop beat the single prompt by 5.4 F1 points, outside the 0.05 to 0.07 run-to-run noise, so it became the default. Inlining the playbook into the prompt cost 14 points; exposing it as a tool was neutral. The router I had built did not earn its place and is now an opt-in cost lever.

SEC Filings Lakehouse

AI-ready Iceberg lakehouse on real EDGAR filings

7.07M point-in-time financial facts with every restated version kept, so "what did we know on date D" is one predicate. dbt with an enforced contract, 10-K and 10-Q text chunked and embedded into pgvector as immutable index versions behind a retrieval-eval gate, a FastAPI RAG endpoint with citations, Dagster orchestration, Terraform for three clouds.

What went wrong, and what caught it

The promotion gate rejected two of my three embedding indexes and was right both times: one was a retrieval problem, fixed with hybrid search, and one was two bugs of mine in the chunker and the eval itself. 17,977 restated facts in two quarters is why the point-in-time model exists.

GitHub Archive Streaming Lakehouse

Kafka to Iceberg, exactly once, with CDC and FinOps

GH Archive events replayed onto Redpanda as Avro with a schema registry, Spark Structured Streaming writing exactly-once into Iceberg with watermarks and RocksDB state, Debezium CDC folded into an SCD2 dimension, replay and backfill, Prometheus and Grafana, and a cost model that prices three AWS designs and says which one to pick.

What went wrong, and what caught it

The first run put every event in 1970. A freshness gauge I had added because consumer lag says nothing about correctness caught it; lag did not. After a full-hour replay the table held 169,753 events with 169,753 distinct ids: zero duplicates. The README lists five things that broke.

Stack Overflow Retention

Causal inference on 1.77M new contributors

Does a fast first answer make new contributors stay? A five-step BigQuery pipeline (44 GB scanned for $0.22) and four estimators: controlled OLS, IPW, propensity stratification and 2SLS. The estimators live in a tested module, the dashboard reads committed summaries, and the whole thing ships as a Docker image.

What the analysis found

The three controlled estimators agree on about +7.7 points of 30-day retention. The instrumental-variable estimate came out at −20 points with a strong first stage, which says the exclusion restriction does not hold. It is reported as a failure, not dropped.

How I work

The evaluation decides, not the architecture diagram

1

Write the eval before trusting the feature

Every agent ships with a scored harness, checkpoints and a resume flag. When the harness said my deliberation layer, my router or my specialist pipeline was not earning its cost, the default changed and the report stayed in the repo.

2

Keep the account of what went wrong

Each README has a section on what broke: the 1970 timestamps, the merge that read a stale cache, the eval that was itself wrong. The bugs were real and the fixes are in the code. I would rather you read them there than find them in an interview.

3

Local first, then cloud, then verified

Every system runs on a laptop with Docker Compose. The Terraform for AWS, Azure and GCP is applied, and the pipeline is re-run on each target and read back before the README says "verified".
